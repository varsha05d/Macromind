FILE: TextParser.kt
STATUS: New ✅ — rewritten twice this session, final version is current
PURPOSE: Extracts the ingredients list from raw OCR text
STRATEGY 1 — Header-based (primary):
  • Searches every line for trigger keywords:
    "ingredients", "ingredient", "contains", "composition",
    "made with", "made from", "सामग्री", "अवयव"
  • Grabs text after the colon on the header line
  • Collects following lines until a HARD_STOP keyword is found
  • HARD_STOPS: "nutritional information", "nutrition facts",
    "best before", "manufactured", "fssai", "lic. no",
    "batch", "customer care", "पोषण", "भंडारण" etc.
  • Tracks open parentheses — does NOT stop mid-subingredient block
    e.g. "Oil (Cotton Seed, Corn" will not stop at "Corn" even if
    "Corn" alone might match something
  • Stops on lines ending with ":" shorter than 30 chars (section labels)
  • Stops when line ends with "." and buffer is >20 chars (complete sentence)
STRATEGY 2 — Heuristic fallback (when no header found):
  • Scores every line: commas×10, parentheses×4, percentages×6,
    ingredient words×5 (oil, flour, sugar, wheat, dal, masala etc.)
  • Penalises lines with nutrition-value-like patterns ("7.8 g")
  • Takes highest-scoring line and extends forward up to 8 more lines
BUG FIXED (this session): Old HARD_STOPS list was too aggressive — contained
  generic words like "protein", "fat", "energy" that appear in ingredient
  names and was cutting off the list mid-way
CLEANING: Collapses double commas, trims junk, replaces OCR pipe (|) with comma

FILE: NutritionExtractor.kt
STATUS: New ✅ — rewritten 3 times this session, final version handles
        the split-column OCR format proven by real packet testing
PURPOSE: Extracts all nutrition values from raw OCR text
CRITICAL DISCOVERY (from real packet testing, Image 4 in final session):
  OCR reads two-column nutrition tables as TWO SEPARATE BLOCKS:
    Block 1 (all labels):    Energy / Protein / Total Carbohydrate /
                             Sugars / Total Fat / Saturated Fat /
                             Trans Fat / Dietary Fibre / Per 100g
    Block 2 (all values):    457.5 kcal / 21.2 g / 53.8 g / 1.7g /
                             17.5g / 5.1 g / 0.1g / 12.2 g
  Old parsers expected label+value on the SAME line → found nothing
  "Fiber = 100" bug: code grabbed "100" from "Per 100g" line
TWO FORMAT HANDLERS:
  FORMAT B — trySplitFormat() [tried first, more common in Indian OCR]:
    • Classifies each line as:
        Pure label  = matches nutrient keyword AND has no number
        Pure value  = has a number AND matches no nutrient keyword
    • Validates: all labels come before all values in the text
    • Pairs label[0]↔value[0], label[1]↔value[1] by order
    • Maps each pair to the correct NutritionData field
    • Requires ≥3 labels and ≥3 values to activate
    • Trans fat: read and discarded (not a model input field)
  FORMAT A — tryInlineFormat() [fallback]:
    • Standard same-line matching: "Protein 21.2 g"
    • Also handles: "Protein (g)   21.2" (unit in header)
    • Falls through to next line if no number found on label line
ENERGY SPECIAL HANDLING (both formats):
  • Prefers explicit kcal: "1500 kJ / 358 kcal" → takes 358
  • Falls back to kJ→kcal: divides by 4.184, rounds to integer
  • Last resort: takes any number in range 1-10000
SODIUM SPECIAL HANDLING:
  • Detects mg vs g by unit suffix
  • "Salt" label: applies ×0.4 factor (salt → sodium)
  • Magnitude guess: v < 5 → multiply by 1000 (assume grams)
SKIP PATTERNS (lines that are never labels or values):
  "nutritional information", "approximate", "per serve",
  "per 100", "as sold", "rda", "reference"
FIELDS EXTRACTED: energyKcal, fatG, saturatedFatG, carbsG, sugarsG,
                  fiberG, proteinG, sodiumMg, servingSize, per100g flag
ALL FIELDS NULLABLE — null means "not found in this scan"
